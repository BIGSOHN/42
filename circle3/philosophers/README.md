# Philosophers 프로젝트 학습 자료

## 과제 개요

### 문제 상황

- 철학자는 한 명 또는 그 이상 원형 테이블에 앉아 있습니다. 테이블 중앙에 큰 스파게티 그릇이 있습니다.
- 철학자들은 **먹기**, **생각하기**, **잠자기**를 번갈아가며 합니다.
  - 먹는 동안에는 생각하거나 잠들 수 없음
  - 생각하는 동안에는 먹거나 잠들 수 없음
  - 잠자는 동안에는 먹거나 생각할 수 없음
- 테이블 위에는 포크들도 있습니다. **철학자 수만큼의 포크**가 있습니다.
- 포크 하나로만 스파게티를 먹는 것은 매우 불편하기 때문에, 철학자는 식사를 위해 **양손에 하나씩** 오른쪽과 왼쪽의 포크를 집어듭니다.
- 철학자가 식사를 마치면, 포크를 테이블에 다시 놓고 잠들기 시작합니다. 깨어나면, 다시 생각하기 시작합니다.
- **시뮬레이션은 철학자가 굶어 죽으며 중단됩니다.**

### 규칙

- 모든 철학자는 반드시 먹어야 하며 **절대 굶어서는 안 됩니다.**
- 철학자들은 서로 대화하지 않습니다.
- 철학자들은 다른 철학자가 죽음에 임박했는지 알지 못합니다.
- 철학자들이 죽음을 피해야 한다는 것은 굳이 말할 필요도 없습니다.

## Process (프로세스)

**프로세스**: 실행 중인 프로그램

### 1. 프로세스의 구성요소

- **Code (Text)**: 실행할 프로그램의 코드
- **Data**: 전역 변수, 정적 변수
- **Heap**: 동적으로 할당되는 메모리
- **Stack**: 함수 호출, 지역 변수 저장

### 2. 프로세스의 특징

- 독립적인 메모리 공간을 가짐
- 다른 프로세스와 자원을 공유하지 않음
- 각각 고유한 PID (Process ID)를 가짐

### 3. 프로세스의 상태

- **New**: 프로세스 생성
- **Ready**: 실행 대기
- **Running**: CPU에서 실행 중
- **Waiting**: I/O나 이벤트 대기
- **Terminated**: 실행 종료

### 4. 프로세스 간 통신 (IPC)

프로세스끼리 통신이 필요할 때 사용

**방법**

- 파이프 (Pipe)
- 소켓 (Socket)
- 공유 메모리 (Shared Memory)
- 메시지 큐 (Message Queue)

### 5. 장단점

**장점**

- 독립적이라 안정성이 높음
- 다른 프로세스에 영향을 주지 않음

**단점**

- 생성과 컨텍스트 스위칭에 많은 비용
- 프로세스 간 통신이 복잡

## Thread (스레드)

**스레드**: 프로세스 내에서 실제로 실행되는 작업의 가장 작은 단위

- 하나의 프로세스는 여러 개의 스레드를 가질 수 있음

### 스레드의 특징

- 같은 프로세스의 스레드들은 메모리를 공유
- 각 스레드는 독립적인 스택을 가짐
- 매우 가벼워서 생성과 종료가 프로세스보다 빠름

### 멀티스레딩의 장점

- 자원 공유가 쉬움
- 응답성 향상
- 경제성 (프로세스보다 생성 비용이 적음)

### 주의할 점

- **동기화 문제** 발생 가능 (여러 스레드가 같은 자원 접근 시)
- **데드락 위험** (서로 기다리는 상태)

---

## Deadlock (교착상태)

멀티 스레드 프로세스에서 동일한 자원을 여러 곳에서 동시에 접근할 때, **두 개의 스레드가 서로의 락 해제를 무한정 기다리는 상황**

### Deadlock 발생 조건 4가지

1. **상호 배제 (Mutual Exclusion)**

   - 프로세스들이 필요로 하는 자원에 대해 배타적인 통제권 요구
2. **점유 대기 (Hold and Wait)**

   - 프로세스가 할당된 자원을 가진 상태에서 다른 자원을 기다림
3. **비선점 (No Preemption)**

   - 프로세스가 어떤 자원의 사용을 끝날 때까지 그 자원을 뺏을 수 없음
4. **순환 대기 (Circular Wait)**

   - 각 프로세스는 순환적으로 다음 프로세스가 요구하는 자원을 가지고 있음

### 교착상태 해결

이 조건 중 **한 가지라도 만족하지 않으면** 교착 상태는 발생하지 않습니다. 따라서 교착 상태를 막기 위해 4가지 조건 중 한 가지, 주로 **순환대기**를 막음으로써 교착상태를 제거하려고 합니다.

그러나 이번 과제는 **스레드**와 **상호 배제(Mutex)**를 이용하여 문제를 해결하고자 합니다.

## Mutex (Mutual Exclusion)

**뮤텍스**: 여러 스레드가 공유 자원에 동시에 접근하는 것을 막아주는 동기화 도구

### 기본 개념

- 공유 자원을 보호하는 **잠금 (Lock)** 메커니즘
- 한 번에 하나의 스레드만 접근 가능
- 자원 사용이 끝나면 잠금을 해제 **(Unlock)**

### 주요 특징

- **소유권 개념**이 있음 (잠근 스레드만 해제 가능)
- 잠금 실패 시 대기 상태로 전환
- **Deadlock 발생 가능성** 있음

### 주의 사항

- 잠금은 최소한의 시간만 유지
- 잠금 순서를 일관되게 유지
- unlock 잊지 말기

## 함수 공부

### 1. usleep 함수

```c
int usleep(useconds_t usec);
```

#### 기능

지정한 마이크로초 동안 대기 상태가 됩니다. (1000 마이크로초 = 1초)

프로그램에서 밥 먹는 시간과 잠자는 시간을 보내게 해주는 함수입니다.

#### 주의할 점

10000 마이크로초를 대기하기 위해:

- `usleep(1)`을 1000번 하는 것
- `usleep(1000)`을 10번 하는 것

이 둘은 **프로그램 수행에 굉장히 큰 차이**를 보이기 때문에 적절한 수치를 넣어주는 것이 중요합니다.

#### 왜 차이가 날까?

**usleep은 시스템 콜 함수**입니다. 즉, 프로그램이 운영체제에 요청을 하는 것입니다.

시스템 콜을 할 때마다:

1. 프로세스는 유저 모드에서 커널 모드로 전환
2. 컨텍스트 스위치 발생
3. 다시 유저 모드로 돌아옴

이 과정은 **상당한 오버헤드**를 발생시킵니다.

#### Overhead (오버헤드)란?

실제로 필요한 작업 외에 추가로 들어가는 간접적인 시간, 메모리, 자원 등을 의미합니다.

**예시: 식당에서 음식 배달**

- 실제 작업: 음식 만들기
- 오버헤드: 주문 받기, 영수증 출력, 포장하기, 배달하기 등

#### Context Switching (컨텍스트 스위칭)

여러 개의 프로세스가 실행되고 있을 때, 기존에 실행되던 프로세스를 중단하고 다른 프로세스를 실행하는 것

CPU가 현재 실행 중인 프로세스/스레드에서 다른 프로세스/스레드로 전환하는 과정

**예시: 공부하다가 다른 과목으로 바꾸기**

- 수학 문제 풀다가 영어 문제로 바꿔 푸는 것
  1. 수학 교재를 치우고
  2. 영어 교재를 꺼내고
  3. 지금까지 풀던 수학 진도를 기억하고
  4. 영어 공부하던 부분을 찾음

**컴퓨터의 경우**

1. 현재 프로세스의 상태 저장
2. 새로운 프로세스 상태 복원

### 2. gettimeofday 함수

```c
int gettimeofday(struct timeval *tv, struct timezone *tz);

struct timeval {
    time_t      tv_sec;
    suseconds_t tv_usec;
}
```

#### 기능

반환값이 구조체에 담기게 되는데, **1970-01-01 00:00부터 함수가 호출된 시간까지의 마이크로초 값**이 반환됩니다.

이것으로 프로그램 시작 이후 몇 초가 지났는지 알 수 있습니다.

#### 매개변수

- **tv**: 시간 정보를 저장할 구조체 포인터
- **tz**: 타임존 정보 (현대에 이르러서는 거의 사용하지 않으므로 `NULL`로 넣어주면 됨)

### 3. pthread_create 함수

```c
int pthread_create(pthread_t *thread, const pthread_attr_t *attr, 
                   void*(*start_routine)(void *), void *arg);
```

#### 사용 예시

```c
pthread_t    pthread;
int          thread_id;

thread_id = pthread_create(&pthread, NULL, function, &args);
```

#### 기능

스레드를 생성할 수 있습니다. 스레드를 생성하면 `function`을 수행하도록 하고, function에 필요한 인자를 `args`에 입력하여 보냅니다.

#### 매개변수

1. **thread**: 스레드를 담을 주소 (미리 `pthread_t`를 선언한 다음 주소를 넣어줌)
2. **attr**: 스레드 속성 (이번 과제에서 사용하지 않으므로 `NULL`)
3. **start_routine**: 스레드에서 동작할 함수의 포인터
4. **arg**: 세 번째 인자에서 불러온 함수 포인터에서 사용할 인자

---

### 4. pthread_join 함수

```c
int pthread_join(pthread_t thread, void **value_ptr);
```

#### 기능

특정 스레드의 작업이 종료될 때까지 기다린 다음 해당 스레드의 자원을 반납합니다.

#### 매개변수

1. **thread**: 기다릴 스레드의 ID
2. **value_ptr**: 스레드의 리턴값 (사용하지 않을 경우 `NULL`)

---

### 5. pthread_detach 함수

```c
int pthread_detach(pthread_t thread);
```

#### 기능

특정 스레드를 즉시 종료시킵니다.

#### 매개변수

- **thread**: 중지할 스레드의 ID

**주의**: `join`과 `detach`를 잘 구분해서 사용해야 합니다.

---

### 6. pthread_mutex_init 함수

```c
int pthread_mutex_init(pthread_mutex_t *restrict mutex, 
                       const pthread_mutexattr_t *restrict attr);
```

#### 기능

뮤텍스를 만드는 함수

#### 매개변수

1. **mutex**: 뮤텍스의 주소
2. **attr**: 뮤텍스의 속성 (이번 과제에서 속성은 사용하지 않으므로 `NULL`)

---

### 7. pthread_mutex_destroy 함수

```c
int pthread_mutex_destroy(pthread_mutex_t *mutex);
```

#### 기능

뮤텍스에 할당한 메모리를 해제하는 함수

#### 매개변수

- **mutex**: 해제할 뮤텍스의 주소

#### 주의사항

해제할 뮤텍스는 **반드시 unlock 상태**여야 합니다.

- lock 된 상태의 뮤텍스에 대한 해제는 **UB (Undefined Behavior)**

---

### 8. pthread_mutex_lock 함수

```c
int pthread_mutex_lock(pthread_mutex_t *mutex);
```

#### 기능

뮤텍스를 잠가서 다른 스레드에서 해당 뮤텍스에 접근할 수 없도록 합니다.

#### 매개변수

- **mutex**: 잠글 뮤텍스의 주소

---

### 9. pthread_mutex_unlock 함수

```c
int pthread_mutex_unlock(pthread_mutex_t *mutex);
```

#### 기능

잠근 뮤텍스를 해제합니다.

#### 매개변수

- **mutex**: 해제할 뮤텍스의 주소

#### 주의사항

잠그지 않은 스레드 외 다른 스레드에서 해제 시 **UB (Undefined Behavior)**입니다.
