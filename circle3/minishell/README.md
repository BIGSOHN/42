# Minishell

> Bash를 재구현하며 쉘의 내부 동작을 이해하는 프로젝트

Minishell은 bash 쉘의 기본 기능을 C언어로 구현한 프로젝트입니다. 프로세스 제어, 파이프라인, 리다이렉션, 시그널 처리 등 운영체제의 핵심 개념을 직접 구현하며 학습했습니다.

## 주요 기능

### 기본 기능
- **프롬프트 표시**: 명령 입력을 기다리는 인터랙티브 프롬프트
- **명령 실행**: PATH 환경 변수 기반 실행 파일 검색 및 실행
- **히스토리**: 방향키로 이전 명령어 탐색 가능

### 파이프라인 & 리다이렉션
- **파이프 (`|`)**: 여러 명령을 연결하여 출력을 다음 명령의 입력으로 전달
- **입력 리다이렉션 (`<`)**: 파일에서 입력 읽기
- **출력 리다이렉션 (`>`, `>>`)**: 파일로 출력 저장 (덮어쓰기/추가)
- **Here Document (`<<`)**: 구분자까지 여러 줄 입력 받기

### 환경 변수
- **변수 확장**: `$VAR` 형태로 환경 변수 값 사용
- **종료 상태**: `$?`로 마지막 명령의 종료 코드 확인

### 따옴표 처리
- **작은따옴표 (`'`)**: 모든 특수 문자를 일반 문자로 처리
- **큰따옴표 (`"`)**: `$`를 제외한 특수 문자를 일반 문자로 처리

### 시그널 처리
- **`Ctrl-C`**: 현재 명령 중단 후 새 프롬프트 표시
- **`Ctrl-D`**: EOF 입력, 쉘 종료
- **`Ctrl-\`**: 무시 (bash와 동일하게 동작)

### 내장 명령어 (Builtins)
- `echo [-n]`: 문자열 출력
- `cd [경로]`: 디렉토리 이동
- `pwd`: 현재 작업 디렉토리 출력
- `export [변수=값]`: 환경 변수 설정
- `unset [변수]`: 환경 변수 제거
- `env`: 환경 변수 목록 출력
- `exit [코드]`: 쉘 종료

## 기술 스택

**언어 및 라이브러리**
- C (C99 표준)
- GNU Readline Library
- libft (자체 제작 유틸리티 라이브러리)

**시스템 함수**
- 프로세스 관리: `fork`, `execve`, `wait`, `waitpid`
- 파일 디스크립터: `pipe`, `dup`, `dup2`, `open`, `close`, `read`
- 시그널 처리: `signal`, `sigaction`, `kill`
- 터미널 제어: `tcgetattr`, `tcsetattr`

## 빌드 및 실행

### 요구사항
- GCC 컴파일러
- GNU Make
- readline 라이브러리 (`readline-devel` 또는 `libreadline-dev`)

### 빌드
```bash
# 컴파일
make

# 정리
make clean   # 오브젝트 파일 삭제
make fclean  # 전체 삭제
make re      # 재컴파일
```

### 실행
```bash
./minishell
```

### 사용 예시
```bash
minishell> echo "Hello, World!"
Hello, World!

minishell> ls -la | grep minishell | wc -l
1

minishell> cat << EOF > test.txt
> Hello
> World
> EOF

minishell> export MY_VAR=42
minishell> echo $MY_VAR
42

minishell> exit
```

## 구현 내용

### 아키텍처 개요

Minishell은 인터프리터의 기본 구조인 **Read-Eval-Print Loop (REPL)** 패턴을 따라 구현되었습니다:

```
입력 (readline) → 렉싱 (Lexing) → 파싱 (Parsing) → 실행 (Execution)
```

### 1. 렉싱 (Lexing)
**파일**: `lexer.c`, `lexer_utils.c`

입력 문자열을 의미 있는 최소 단위인 토큰으로 분리합니다.

- **따옴표 처리**: 작은따옴표/큰따옴표 내부 문자 구분
- **연산자 인식**: 파이프(`|`), 리다이렉션(`<`, `>`, `<<`, `>>`) 구분
- **환경 변수 확장**: `$VAR`, `$?` 처리
- **공백 분리**: 토큰 경계 결정

### 2. 파싱 (Parsing)
**파일**: `parser.c`, `parser2.c`, `parser_utils.c`

토큰을 문법 구조에 맞게 해석하여 실행 가능한 명령 트리를 생성합니다.

- **프랫 파싱 알고리즘** 사용 (연산자 우선순위 기반)
- **연산자 우선순위**:
  1. 서브쉘 `( )`
  2. 리다이렉션 `<`, `<<`, `>`, `>>`
  3. 파이프 `|`
  4. 논리 연산 `&&`, `||`
- **구문 오류 검사**: 닫히지 않은 따옴표, 잘못된 연산자 배치 등

**구현 파일**: `ebnf.c` (문법 규칙 정의)

### 3. 실행 (Execution)
**파일**: `execute_command.c`, `simple_command.c`, `shell_command.c`

파싱된 명령 트리를 순회하며 실제 명령을 실행합니다.

- **프로세스 생성**: `fork`로 자식 프로세스 생성
- **파이프라인 구축**: `pipe`, `dup2`로 표준 입출력 재설정
- **리다이렉션 처리**: 파일 디스크립터 조작
- **내장 명령어**: 별도 프로세스 없이 직접 실행
- **종료 상태 관리**: `$?` 변수 업데이트

### 4. 시그널 처리
**파일**: `signal.c`

사용자 인터럽트를 적절히 처리합니다.

- **대화형 모드**: `Ctrl-C`로 새 프롬프트, `Ctrl-D`로 종료
- **명령 실행 중**: 자식 프로세스에만 시그널 전달
- **전역 변수 제한**: 시그널 플래그 1개만 사용 (과제 요구사항)

### 5. 메모리 관리
**파일**: `exit_utils.c`, `error_handler.c`

모든 동적 할당 메모리를 추적하여 누수 방지합니다.

- 토큰 리스트, 환경 변수 리스트 등 자료구조 관리
- 오류 발생 시 안전한 정리 보장
- Valgrind로 메모리 누수 검증 완료

## 주요 학습 내용

### 1. 프로세스 관리
- **fork의 동작 원리**: 부모/자식 프로세스의 메모리 공간 분리
- **execve의 활용**: 프로세스 이미지 교체
- **프로세스 대기**: `wait`/`waitpid`로 좀비 프로세스 방지

### 2. 파일 디스크립터와 I/O 리다이렉션
- **파일 디스크립터 복제**: `dup`/`dup2`를 활용한 표준 입출력 재설정
- **파이프 구현**: `pipe`로 프로세스 간 통신
- **백업 및 복구**: 원본 stdin/stdout 보존 후 복구

### 3. 파싱 알고리즘
- **프랫 파싱**: 연산자 우선순위를 바인딩 파워로 표현
- **재귀 하향 파싱**: 문법 구조를 함수 호출로 매핑
- **AST 구축**: 실행 가능한 명령 트리 생성

### 4. 시그널 처리
- **시그널 핸들러**: 비동기 이벤트 처리
- **터미널 모드**: Canonical/Non-canonical 입력 모드 제어
- **경쟁 조건**: 전역 변수 최소화로 안정성 확보

### 5. 어려웠던 점과 해결

**문제 1: 파이프라인에서의 파일 디스크립터 관리**
- 여러 명령이 연결될 때 불필요한 FD가 열린 채로 남는 문제 발생
- 해결: 각 명령 실행 후 사용하지 않는 FD를 즉시 닫도록 수정

**문제 2: Here Document 구현**
- 입력을 어디에 저장할지, 언제 읽을지 결정이 어려움
- 해결: 임시 파일 대신 파이프를 사용하여 메모리에서 처리

**문제 3: 따옴표 내부 환경 변수 처리**
- 작은따옴표/큰따옴표의 동작 차이 구현
- 해결: 토큰화 단계에서 따옴표 타입을 플래그로 관리
