# cub3D

레이캐스팅 기반 3D 미로 게임 - Wolfenstein 3D 오마주

## 프로젝트 개요

cub3D는 1992년 Wolfenstein 3D에서 사용된 레이캐스팅 기술을 활용하여 3D 미로를 렌더링하는 프로젝트입니다. MiniLibX 그래픽 라이브러리를 사용하여 1인칭 시점의 3D 미로 탐험 게임을 구현했습니다.

### 팀 역할 분배
- **손승모**: 맵 파일 파싱 및 검증 시스템
- **팀원**: 레이캐스팅 엔진 및 렌더링

## 주요 기능

### 1. 맵 파일 파싱 (.cub 파일)
`.cub` 확장자 파일에서 게임 설정과 맵 데이터를 파싱:

```
NO ./path/to/north_texture.xpm
SO ./path/to/south_texture.xpm
WE ./path/to/west_texture.xpm
EA ./path/to/east_texture.xpm

F 173,187,214    # Floor RGB 색상
C 0,240,255      # Ceiling RGB 색상

1111111111
1000000001
100N000001    # N: 플레이어 시작 위치 (북쪽 방향)
1000000001
1111111111
```

#### 파싱 요소
- **텍스처 경로**: 4방향(북, 남, 서, 동) 벽 텍스처 파일 경로
- **색상 정보**: 바닥(F)과 천장(C)의 RGB 값 (0-255 범위)
- **맵 레이아웃**: 1(벽), 0(빈 공간), N/S/E/W(플레이어 시작 위치 및 방향)

### 2. 맵 검증 시스템
게임의 무결성을 보장하기 위한 다층 검증:

- **파일 형식 검증**: `.cub` 확장자 확인, 파일 접근 권한 확인
- **텍스처 검증**:
  - 4개 방향 텍스처 파일 존재 여부
  - `.xpm` 형식 확인
  - 파일 접근 가능 여부
- **색상 검증**:
  - RGB 각 값이 0-255 범위 내
  - 올바른 형식 (R,G,B)
- **맵 검증**:
  - 맵이 벽으로 완전히 둘러싸여 있는지 확인
  - 불규칙한 형태의 맵에서도 작동하는 검증 알고리즘
  - 플레이어 시작 위치가 정확히 1개인지 확인
  - 유효하지 않은 문자 검출

### 3. 레이캐스팅 렌더링
- DDA(Digital Differential Analysis) 알고리즘을 통한 레이캐스팅
- 벽까지의 거리 계산 및 원근 효과
- 텍스처 매핑을 통한 벽면 렌더링

### 4. 플레이어 이동 및 시점 전환
- **이동**: W, A, S, D 키
- **회전**: 왼쪽/오른쪽 화살표 키
- 부드러운 시점 전환

## 빌드 및 실행

### 요구사항
- GCC 컴파일러
- MiniLibX 그래픽 라이브러리
- X11 (Linux)

### 빌드
```bash
make
```

### 실행
```bash
./cub3D [map_file.cub]
```

예시:
```bash
./cub3D test.cub
```

### 정리
```bash
make clean   # 오브젝트 파일 삭제
make fclean  # 실행 파일 포함 전체 삭제
make re      # 재빌드
```

## 맵 파일 형식

### 기본 구조
```
NO ./textures/north.xpm
SO ./textures/south.xpm
WE ./textures/west.xpm
EA ./textures/east.xpm

F 220,100,0
C 225,30,0

        1111111111111111111111111
        1000000000110000000000001
        1011000001110000000000001
        1001000000000000000000001
111111111011000001110000000000001
100000000011000001110111111111111
11110111111111011100000010001
11110111111111011101010010001
11000000110101011100000000011
10000000000001111100000000001
10000000000111111010100100011
110000011101111111101111N00111
11110111 1110101 101111010001
11111111 1111111 111111111111
```

### 맵 문자 설명
- `1`: 벽
- `0`: 빈 공간 (이동 가능)
- `N`: 플레이어 시작 위치 (북쪽 방향)
- `S`: 플레이어 시작 위치 (남쪽 방향)
- `E`: 플레이어 시작 위치 (동쪽 방향)
- `W`: 플레이어 시작 위치 (서쪽 방향)
- ` ` (공백): 맵 외부 (벽으로 처리)

### 맵 규칙
1. 맵은 벽(1)으로 완전히 둘러싸여야 함
2. 플레이어 시작 위치는 정확히 1개만 존재해야 함
3. 맵은 불규칙한 형태 가능 (직사각형일 필요 없음)

## 기술적 하이라이트

### 맵 파싱 시스템 (담당 부분)
1. **파일 읽기 및 토큰화**
   - 줄 단위로 파일 읽기
   - 텍스처, 색상, 맵 데이터 분리

2. **데이터 검증**
   - 각 요소의 형식 및 유효성 검사
   - 에러 메시지를 통한 명확한 오류 보고

3. **맵 경계 검증 알고리즘**
   - 불규칙한 형태의 맵을 위한 범람 채우기(Flood Fill) 또는 경계 추적 알고리즘
   - 모든 이동 가능한 공간이 벽으로 둘러싸여 있는지 확인

### 레이캐스팅 엔진
1. **레이 투사**: 화면의 각 수직선마다 레이 투사
2. **벽 감지**: DDA 알고리즘으로 벽과의 충돌 지점 계산
3. **거리 계산**: 어안 렌즈 효과 보정
4. **텍스처 매핑**: 벽면에 텍스처 적용

## 기술 스택

- **언어**: C
- **그래픽 라이브러리**: MiniLibX
- **수학**: 삼각함수, 벡터 연산
- **알고리즘**:
  - DDA (Digital Differential Analysis)
  - 레이캐스팅
  - 맵 검증 (Flood Fill / 경계 추적)
- **빌드 시스템**: Makefile
- **컴파일 옵션**: `-Wall -Wextra -Werror`

## 학습 포인트

이 프로젝트를 통해 다음을 학습했습니다:

1. **그래픽 프로그래밍**: 픽셀 단위 렌더링, 버퍼 관리
2. **레이캐스팅**: 2D 맵을 3D 시점으로 변환하는 알고리즘
3. **파일 파싱**: 복잡한 형식의 설정 파일 처리
4. **데이터 검증**: 엣지 케이스를 고려한 견고한 검증 시스템
5. **그래프 알고리즘**: 불규칙한 맵의 경계 검증
6. **수학**: 삼각함수, 벡터, 좌표 변환
7. **팀 협업**: 파싱과 렌더링 모듈의 명확한 인터페이스 설계

## 조작법

- `W`: 전진
- `S`: 후진
- `A`: 왼쪽으로 이동
- `D`: 오른쪽으로 이동
- `←`: 왼쪽으로 회전
- `→`: 오른쪽으로 회전
- `ESC`: 게임 종료
