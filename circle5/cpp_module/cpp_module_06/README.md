# C++ Module 06 - C++ Casts

| Cast 종류 | 용도 | 안전성 | 컴파일/런타임 | 사용 예시 |
|-----------|------|--------|---------------|-----------|
| `static_cast` | 명시적 타입 변환 | 중간 | 컴파일 타임 | `static_cast<float>(42)` |
| `dynamic_cast` | 다형성 다운캐스팅 | 높음 | 런타임 | `dynamic_cast<Derived*>(base)` |
| `const_cast` | const 속성 변경 | 낮음 | 컴파일 타임 | `const_cast<int*>(const_ptr)` |
| `reinterpret_cast` | 비트 재해석 | 매우 낮음 | 컴파일 타임 | `reinterpret_cast<uintptr_t>(ptr)` |

## Exercise 00 : Conversion of scalar types

### static_cast

- 컴파일 타임에 타입 체크
- 안전한 타입 변환만 허용
- 스칼라 타입 간 변환에 사용
- 제한적 안전
- 잘못된 캐스팅 가능
- 빠름

#### 컴파일 타임에 타입 체크

- 컴파일 타임 체크 = 프로그램 실행 전, 컴파일러가 타입 변환이 가능한지 검사
- 문법적으로 변환 가능한가?를 체크
- 실행 시 실제로 그 타입인지 여부는 체크를 하지 않음

#### 안전한 타입 변환만 허용

- 안전 = 문법적으로 의미 있는 변환
- 관련 없는 포인터 변환, const 제거, 비트 재해석 불가

### NaN (Not a Number)

- Q. 왜 num != num인가?
- A. IEEE 754 표준 : NaN은 어떤 값과도 같지 않음 (자기 자신 포함!)

## Exercise 01 : Serialization

### dynamic_cast

#### 개념

- 런타임에 타입 체크
- 다형성이 있는 클래스에만 사용 가능(virtual 함수 필요)
- 실패시 nullptr 반환(포인터) 또는 예외 발생 (참조)

### reinterpret_cast

- 포인터 <-> 정수 변환 (직렬화 / 역직렬화)
- 포인터를 정수로, 정수를 포인터로 변환
- 비트 패턴 그대로 재해석
- 매우 위험하지만 Low-level 작업에 필요

### 직렬화 (Serialization)

- 포인터를 정수로 변환
- reinterpret_cast<uintptr_t>(ptr)
- 메모리 주소를 숫자로 저장 (포인터의 16진수 값을 10진수 정수로 변환)

### 역직렬화 (Deserialization)

- 정수를 포인터로 변환
- reinterpret_cast<Data*>(ptr)
- 저장된 주소로 다시 접근

### why 직렬화, 역직렬화

- 포인터는 파일 / 네트워크로 전송 불가
- 정수는 전송 / 저장 가능
- 나중에 다시 포인터로 복원
- uintptr_t로 변환하면 주소를 정수로 다룬다는 의도가 
명확해짐
- 프로그램 종료하면 객체는 사라짐 숫자로 변환 후 파일에 저장하는 방식으로 하기 위함
- 포인터는 같은 프로세스 내에서만 유효 즉 포인터는 의미 없음
- 객체 내용을 바이트로 변환해서 전송해서 받는 쪽에서 새로운 객체 생성을 함
- ex01에서는 이 과정을 하지 않음

### uintptr_t

- 포인터를 저장할 수 있는 정수 타입
- 플랫폼 독립적

### 주의사항
- 원본 객체가 삭제되면 역직렬화 불가 (댕글링 포인터)
- 메모리 주소만 저장 (객체 내용은 저장 안 됨)

## Exercise 02 Identify real type

### dynamic_cast

- 런타임 타입 식별 (RTTI)
- 다형적 클래스만 사용 가능 (virtual 함수 필요)
- 안전한 다운 캐스팅

#### 런타임 타입 식별

- 프로그램 실행 중에 실제 타입을 확인
- 왜 필요한가?
	- 다형성의 한계 : 포인터 타입으로는 자식의 고유 기능에 접근 불가
- 느리지만 유연함

### 왜 참조는 예외?

- 참조는 "null 참조" 불가능
- 실패를 표현할 방법 = 예외만 가능
