# C++ Module 07 - C++ Templates

| 개념 | 설명 | 대표적 예시 |
| --- | --- | --- |
| 함수 템플릿(Function Templates) | 여러 타입에 대해 동일한 알고리즘을 적용하는 함수 | `template <typename T>` |
| 클래스 템플릿(Class Templates) | 여러 타입의 데이터를 저장할 수 있는 클래스 | `Array<T>`, `std::vector<T>` |
| 템플릿 인스턴스화 | 컴파일 시 구체적인 타입으로 템플릿을 생성 | `swap<int>(a, b)` |

## 템플릿 핵심 정리

### 왜 템플릿을 사용하는가?

1. **코드 재사용** : 한 번 작성으로 여러 타입에 사용
2. **타입 안정성** : 컴파일 시 타입 체크
3. **성능** : 런타임 오버헤드 없음
4. **유연성** : 다양한 타입과 알고리즘 조합

### 템플릿 사용 시 주의사항

1. **헤더에 정의** : 템플릿은 헤더 파일에 구현 필수
2. **타입 요구사항** : 사용하는 연산을 타입이 지원해야 함
3. **코드 크기** : 각 타입마다 코드 생성 -> 바이너리 증가
4. **에러 메시지** : 템플릿 에러는 매우 길고 복잡할 수 있음

## Exercise 00: Start with a few functions

### 함수 탬플릿 (Function Templates)

- 템플릿 함수는 여러 타입에 대해 동일한 알고리즘을 적용
- `template <typename T>` 구문으로 선언
- 컴파일 시점에 필요한 타입으로 인스턴스화 됨
- `typename`과 `class` 키워드는 동일 (관례상 `typename` 선호)

```cpp
template <typename T> 
void swap(T& a, T& b) {
    T tmp = a;
    a = b;
    b = tmp;
}
```

### 헤더 파일에 구현

- **템플릿은 반드시 헤더 파일에 정의해야 함**
- 이유 : 컴파일러가 템플릿을 인스턴스화하려면 전체 정의가 필요

## Exercise 01: Iter

### 함수 포인터와 템플릿

- 템플릿 함수는 다른 함수의 매개변수로 전달 가능
- 콜백 패턴의 기초가 됨

```cpp
template <typename T, typename Func> 
void iter(T* array, size_t length, Func func) {
    for (size_t i = 0; i < length; i++) {
        func(array[i]);
    }
}
```

### 왜 `Func`를 별도 템플릿 파라미터로?

## Exercise 02: Array

### 클래스 템플릿

- **여러 타입의 데이터를 다룰 수 있는 클래스의 설계도

#### 핵심 차이

- 함수 템플릿: `func(42)` → 컴파일러가 자동으로 타입 추론
- 클래스 템플릿: `Array<int> arr` → 타입을 명시적으로 지정해야 함

### 클래스 템플릿 vs 함수 템플릿

| | 함수 템플릿 | 클래스 템플릿 |
|---|---|---|
| 타입 지정 | 자동 추론 가능 | 명시적으로 지정 필수 |
| 사용 예시 | `swap(a, b)` | `Array<int> arr` |
| 인스턴스화 | 호출 시 자동 | 객체 생성 시 |
